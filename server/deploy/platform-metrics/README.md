# Platform metrics receiver

Disabled by default. Configure `PLATFORM_METRICS_ENABLED=true`, a protected `PLATFORM_METRICS_TOKEN_FILE` (one random bearer token), and `PLATFORM_METRICS_DB_URL` (a separate `postgresql+asyncpg` writer login). Keep secrets outside Git and logs. Restart on DSN rotation; token file is read per request. Never use the household database login as writer.

SQL files are operator-reviewed deployment artifacts and have not been applied. Provision owner, writer, reader, maintenance roles and database CONNECT separately, then apply schema and grants with an administrator. Inspect PUBLIC and inherited grants; verify allowed and forbidden operations using actual roles. Grant reader access to the actual Grafana role only after verifying it. Schedule bounded cleanup as a single non-overlapping job and monitor failures and storage. Review backups before rollback.

The application applies a per-process token bucket (60/minute, burst 10); a shared frontend limit is required across multiple workers. Configure the existing HTTPS frontend for the exact route with 64 KiB limit, equivalent shared rate limiting, short timeouts and no body or Authorization logging. Verify actual vhost, TLS, logging and service deployment separately; no live configuration is modified here.

## Local PostgreSQL integration evidence (2026-11-13)

`PM_PG_FIXTURE=1 server/.venv/bin/python -m pytest server/tests/integration/test_platform_metrics_postgres.py -q` passed against the locally cached pinned `postgres:16.10-alpine` image on Docker `desktop-linux`. The test creates one randomly named loopback-only container with one CPU and 384 MiB limits, fixture-only random credentials, and removes its container and anonymous volume afterwards. It exercises the migration and grants, accepted/duplicate/conflict HTTP responses, concurrent duplicate insert, transactional rollback, denial of writer DDL/DELETE/household insert, maintenance cleanup and schema rollback while preserving a household fixture row. The cleanup test caught and corrected a permission mismatch: a single non-overlapping cleanup job is required.

This is a local fixture, not proof of production roles, inherited/PUBLIC privileges, concurrent cleanup, live TLS or proxy limits, backup/restore, production migrations, or deployment behavior. Docker must have the pinned image cached; the test never pulls it.

## Standalone packaging (templates only)

The isolated app imports the accepted receiver router directly and has no household lifespan. `/healthz` is process liveness only, not DB readiness. The Dockerfile uses a valid local base tag and copies only the accepted config and receiver plus the standalone entrypoint. `prepare-build.sh --dry-run` checks a clean checkout, accepted PM1 config/router, the recorded base image ID and platform, the local tag if present, and the selected Docker context's same-named buildx builder, its matching endpoint, `docker` driver and linux/amd64 support; it makes no image changes. All image and build commands are pinned to that context; a mismatched or ambiguous builder endpoint is refused. After review, `prepare-build.sh --build` tags that exact image locally, verifies the tag before and after building, and invokes buildx with `--pull=false`, `--platform linux/amd64` and `--load`. The script refuses an already occupied mismatching base tag and must run with one trusted operator and no concurrent retagging. Verify inherited image environment and resulting image contents and record the output ID before rollout. The target builder's local-tag resolution still needs a separately authorized build test; no build or deployment is implied by these templates.

Review the systemd receiver template against the actual host: replace the image placeholder with the reviewed local derived image ID, confirm `127.0.0.1:8330` is free, and provision `/etc/platform-metrics/receiver.env` with only `PLATFORM_METRICS_ENABLED=true` and the separate `PLATFORM_METRICS_DB_URL`. The environment file must be root-readable only. Provision a random token at `/etc/platform-metrics/writer-secret/token`, with its dedicated directory containing no other files and access limited to root and the container's numeric GID 65532; ensure parent directories are traversable. The directory bind mount allows atomic token-file replacement to be observed by the receiver. No household env files or credentials are mounted. Verify Docker host networking and local PostgreSQL access on the target; the app binds loopback only. Use one worker. Docker exposes environment to privileged Docker administrators; restrict Docker access and rotate/revoke secrets if needed.

The nginx template consists of an `http` zone and exact location blocks for the *verified* existing HTTPS vhost. The shared zone key covers the writer endpoint per server name and can be exhausted by unauthorized requests; protect the frontend appropriately. Check existing error logs for request-body/header capture, ensure the exact route and zone do not conflict, test configuration before reload, and verify 413, 429 with Retry-After and no credential logging. The application limit is also per process. No household routes or Grafana settings are changed by this package.

The cleanup unit/timer uses a distinct maintenance login and a protected libpq `PGPASSFILE` owned by the maintenance user and mode 0600. Replace its database placeholder and verify the installed cleanup SQL. Systemd does not start another instance of the same active oneshot unit; do not schedule additional invocations. Monitor service failures and storage. The timer does not provision roles, credentials or schema.

Keep the existing CM container and its image untouched. Data/schema removal is separate and destructive; review backup and explicit approval before the supplied SQL rollback.
