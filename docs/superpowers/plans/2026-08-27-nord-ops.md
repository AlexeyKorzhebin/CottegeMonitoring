# Nord Ops Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Один каталог Ops в Nord: REST-грань и MCP-грань вызывают одни handlers, дом в контракте, OpenClaw skill/AGENTS.md в том же изменении.

**Architecture:** Реестр `OpSpec` → диспетчер `authorize` + rate-limit + handler. MCP tools и `POST /api/v1/houses/{house_id}/ops/{name}` генерируются из реестра. Ресурсный REST по GA не проецируется в MCP. Grafana не трогаем. HA **не** деплоим в этом плане — она станет клиентом REST-грани после него (см. конец документа).

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2 async, Alembic, FastMCP (`mcp>=1.0,<2` — не SDK 2.x), pytest/httpx.

**Spec:** `docs/superpowers/specs/2026-08-27-nord-ops-design.md`

## Global Constraints

- Один процесс: `/mcp` остаётся mount в FastAPI (`server/src/cottage_monitoring/main.py`). Sidecar MCP запрещён.
- Имена MCP tools не переименовывать. Новое имя только `list_houses`.
- `house_id` на house-scoped tools — optional; один грант — можно опустить; >1 без аргумента → 400, не угадывать первый дом.
- Все house-scoped Ops по REST: `POST /api/v1/houses/{house_id}/ops/{name}` (включая read). Каталог: `GET /api/v1/ops`.
- `list_houses` не house-scoped: REST = существующий `GET /api/v1/houses` (тот же handler). Отдельного `POST /ops/list_houses` нет.
- Запрещено `@mcp.tool` и ручной FastAPI-роут той же семантики в обход реестра.
- `AUTH_REQUIRED=false` (dev/test): `GET /houses` по-прежнему все дома.
- Grafana не вызывает `command_service` / MQTT.
- TOOLS.md vs AGENTS.md (mcporter) — не этот план; GitHub issue #4.
- MCP Python SDK 2.x / spec 2026-07-28 stateless — не этот план; GitHub issue (Nord остаётся `mcp>=1.0,<2` + FastMCP session_manager).
- HA Container / MQTT Discovery / KNX — не этот план.
- Коммиты только если пользователь явно попросил; иначе оставлять working tree.
- Тесты: `cd server && python -m pytest <path> -v`. Python 3.12.

```python
@dataclass(frozen=True)
class OpSpec:
    name: str
    permission: Literal["read", "write"]
    house_scoped: bool
    description: str
    handler: Callable[..., Awaitable[dict]]
    params_model: type[BaseModel] | None  # None если параметров нет
```

`resolve_house_id(ctx, house_scoped, requested: str | None) -> str | None`:
- not house_scoped → вернуть None (handler дом не получает)
- house_scoped + requested → authorize read/write later in dispatch; здесь только: если requested not in house_ids → raise HTTP 403; иначе requested
- house_scoped + requested is None + len==1 → that id
- house_scoped + requested is None + len!=1 → HTTP 400 `"house_id required"`
- len==0 → 403

`dispatch(ctx, spec, *, house_id: str | None, params: dict, session) -> dict`:
1. permission vs scopes → 403
2. resolve house
3. if write: `agent_actions.check_write_rate_limit(ctx)` (перенести вызов сюда, убрать из MCP-обёрток в Task 4)
4. call handler: house_scoped → `(session, house_id, **params)`; else → `(session, **params)` плюс ctx/house_ids для `list_houses` — передавать `house_ids=ctx.house_ids` как kwarg, не путать с MQTT house_id.

Для `list_houses` handler signature: `async def list_houses(session, *, house_ids: frozenset[str] | None = None)`. Диспетчер для non-scoped: не подставлять path house_id.

## Как сопряжём Home Assistant (следующая спека, не этот план)

Nord Ops **и есть** стык. HA не подключают к Mosquitto `cm/#` и не к KNX/LogicMachine.

После того как Tasks 1–6 на elion:

1. **HA Container** на elion (не HA OS, аддоны не нужны). Семья логинится в HA; Nord видит только сервисный ключ.
2. **Ключ** `cottage-create-api-key --house <id> --name home-assistant --scopes read,write` — один дом, как OpenClaw.
3. **Транспорт:** REST-грань, не MCP. `/api/` уже на nginx (`monitoring.black-castle.ru`). С хоста/docker: `http://127.0.0.1:8321/api/v1` или HTTPS. `/mcp` для HA не открываем в интернет.
4. **Сущности:** ресурсный REST `GET /houses/{id}/objects` + `GET .../state` (теги `light`/`control`) **или** сразу Ops `list_lights` / `get_climate`. Команды — только `POST /houses/{id}/ops/set_lights` (та же функция, что Telegram `set_lights`).
5. **Автоматизации HA выключить** для дома: сцены остаются в LogicMachine.
6. Тонкий custom component (HACS) предпочтительнее россыпи REST sensors: один клиент, poll state, клик → Ops. MQTT Discovery — только если REST-компонент окажется неудобен; префикс `ha/#` с ACL, не `cm/#`.

Пока REST Ops нет на проде, ставить HA бессмысленно: пришлось бы дублировать семантику в YAML. Поэтому порядок: **этот план → деплой Nord → отдельная спека HA**.
